## 4. SIFT — эталон по качеству

**Говорю (≈30 сек):**
«SIFT ищет экстремумы в пространстве масштабов (DoG), назначает ориентацию по доминирующему градиенту и строит 128‑мерный дескриптор из гистограмм градиентов. Это обеспечивает инвариантность к масштабу и повороту. Матчу `BFMatcher` + `L2`. На Статуе уверенно сопоставляются корона, факел, складки. На Monster даже при частичной окклюзии остаются соответствия на логотипе/тексте. На Таносе совпадения по жёстким краям шлема/брони. Минус — вычислительная цена.»

**Что показываю:**
1) ключевые точки SIFT на эталонах;
2) коллажи матчей: Liberty↔Liberty(другой ракурс), Monster↔Monster(с окклюзией), Thanos↔Thanos;
3) пример Liberty↔Monster (ложные совпадения).

## 5. BRISK — быстрый бинарный компромисс

**Говорю (≈30 сек):**
«BRISK формирует бинарные дескрипторы, сравнение идёт по `Hamming`. Быстрый и лёгкий. На Статуе при умеренной перспективе находит опорные точки, при сильной — часть пар теряется. На Monster чувствителен к бликам/прозрачностям — возможны “липкие” ложные матчи на краях бутылки. На Таносе стабильных пар меньше, чем у SIFT. Итог: хороший баланс для реального времени, но хуже переносимость сложной перспективы/бликов.»

**Что показываю:** ключевые точки BRISK и 2–3 коллажа матчей (аналогичные кейсы).

## 6. ORB — максимально быстрый

**Говорю (≈30 сек):**
«ORB — FAST+BRIEF с учётом ориентации, тоже бинарный (`Hamming`). Силен по скорости. На Статуе работает при небольших поворотах, при сильной перспективе валидных пар меньше. На Monster многие точки уходят в блики/границы бутылки — ограничиваю число лучших матчей. На Таносе находит края брони/лица, но их меньше, чем у SIFT/BRISK. Итог: отличный для ограниченных ресурсов, если сцена без тяжёлой перспективы и засветов.»

**Что показываю:** ключевые точки ORB и коллажи матчей.

## 7. Harris — детектор без дескрипторов

**Говорю (≈30 сек):**
«Harris — детектор углов. Считается отклик R = det(M) − k·(trace(M))² на матрице вторых моментов. Большие R — углы: на Статуе их много на короне/факеле, на Monster — на контуре логотипа, у Таноса — на границах брони. Сам по себе для сопоставления не используется — нужны внешние дескрипторы (например, SIFT/ORB).»

**Что показываю:** визуализации Харриса по всем трём сценам.

Подсказка: как быстро показать BRISK/ORB в этой тетрадке
- Детекция: замените создание детектора на `cv2.BRISK_create()` или `cv2.ORB_create()` и вызовите те же `detect_keypoints(...)`.
- Матчинг: вызывайте `match_keypoints(...)` как для SIFT; для бинарных дескрипторов используйте норму `Hamming`.
- Если отдельных блоков под BRISK/ORB нет, демонстрацию можно провести в блоке SIFT, переинициализировав `detector` и перезапустив те же ячейки визуализации/сопоставления.

Примечания
- SIFT может выдать предупреждение о переносе из `xfeatures2d` — это нормально.
- SURF часто недоступен в стандартных сборках; при отсутствии его секцию можно пропустить.
